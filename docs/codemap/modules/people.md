# People

**Purpose:** HR master data, multi-tenant SAP-style ERP: employee+dated records, org structure (units/jobs/positions/reporting line), position→cost-centre assignment, pay structure (components+GL/cost mapping), time/leave; plus the people side of the authority model — chain of command, authority chart, delegation (CAIRN §16.6/§23). Master-data/definition only — no pay calc/posting; payroll execution awaits owner decision (DV-001, R-11, D-013).

### Pay components & record types (pay structure)
- `src/modules/people/payroll-structure.ts` — payroll phase 1 (9277): salary structures (T510) and their components' amount rule (`FIXED`|`PERCENT_OF_BASE`, never on `pay_component`), employee structure assignment (infotype 0008, inclusive `valid_to`, overlap refused under advisory lock, `requestKey` idempotent), and `validateEmployeeForRun(tx, client, personnelNumber, from, to)` → `{ready, reasons[], notes[]}` (never throws; reasons `NO_STRUCTURE`,`OVERLAPPING_STRUCTURES`,`STRUCTURE_NOT_VALID`,`STRUCTURE_EMPTY`,`COMPONENT_UNMAPPED`,`NO_POSITION`,`NO_COST_CENTRE`,`NO_COMPANY`; `EOS_NOT_SUPPORTED` since 9278; note `CURRENCY_DIFFERS`). Company = position assignment's `company_code`, else its cost centre's; chart/currency from `company_code`. Exports also `defineSalaryStructure`,`changeSalaryStructure`,`setStructureComponent`,`listStructures`,`getStructure`,`listAssignableComponents` (excludes `EOS_PROVISION`),`removeStructureComponent` (9278; delete grant),`assignStructure`,`endAssignment`,`assignmentFor`,`listAssignments`,`employeeRunReadiness`,`defaultPayrollCurrency`, `PayrollStructureError(message, remedy, code)`, `PAYROLL_RESULT_CAPABILITY`. Service signature `(input, capabilities[])` like `pay-components.ts`. Calculates and posts nothing. `setStructureComponent` refuses an `EOS_PROVISION` component (`EOS_NOT_SUPPORTED`).
- `src/modules/people/payroll-run.ts` — payroll phase 2 (9278): `proposePayrollRun` (period dates via `platform/periods.periodDates`, open-period check account type `S`, one live run per company/year/period, `requestKey` idempotent) → `recalculatePayrollRun` (PROPOSED only) → `releasePayrollRun` (refused while exceptions stand, an included employee is unready, or the selection grew: `RUN_STALE`) → frozen; `cancelPayrollRun` (reason required; POSTED refused). Selection = employees with a `position_assignment` in the period whose company (own, else cost centre's) is the run's; each is checked with `validateEmployeeForRun` — unready → `payroll_run_exception` rows; ready → `calculateResult` (in a savepoint; a `PayrollRunError` there becomes an exception too). Pure `payableDaysFor` (clip, merge overlapping unpaid APPROVED absences) and `calculateComponent` (bigint exact, round once half-up to `currency.decimal_places`). Segments: contiguous days with the same position (cost centre) and salary assignment → one line per component per segment. Lines snapshot debit/credit account, cost receiver and cost centre (`ASSIGNMENT` → position's, `FIXED` → config's, `NONE` → null). Readers `listPayrollRuns`,`getPayrollRun`,`listResults`,`getResultWithLines`,`listPayrollCompanies`,`currentPayrollPeriod`. `PayrollRunError(message, remedy, code)`; capability `PEOPLE.PAYROLLRUN.EXECUTE` via `(input, capabilities[])`. Posts nothing (phase 3). **Off-cycle (9281):** a period may hold several runs; `calculateRun` excludes employees another live run of the period covers (`coverageOf`), records them as informational `ALREADY_COVERED` exceptions (not counted in `exception_count`, do not block release; `INFORMATIONAL_EXCEPTIONS`), and sets `predecessor_run_id` to the covering run with most of them. Propose refuses `ALL_COVERED` when every candidate is covered; release refuses `COVERED_ELSEWHERE`; trigger errors become `RUN_RACE` (23505) / `RESULT_FROZEN` (23514).
- `src/modules/people/payroll-posting.ts` — payroll phase 3 (9279): `postPayrollRun({client, changedBy, runId, authorization})` posts a RELEASED run as one `PR` document dated `period_to` through `postGlDocument` (`{ tx, authorization }`, request key `PAYROLL-POST-<runId>`); the run becomes POSTED with `document_number`/`document_fiscal_year`/`posted_by`/`posted_at` inside the `onPosted` hook. Authority: `PEOPLE.PAYROLL.POST` via `verifyServiceAuthorityInTx` + Company Code reach; `FIN.JOURNAL.POST` is asked by the G/L posting. Lines come only from the `payroll_result_line` snapshot (pure `buildPayrollJournal`: group by account+cost centre+component, debits keep cost centre, credits flat, zero dropped, net pay one credit); net pay account from `account_determination` event `PAYROLL_NET_PAY` (never hardcoded). Refusals (`PayrollPostingError` with `code`): `PAYROLL_AUTHORITY`, `COMPANY_SCOPE`, `RUN_UNKNOWN`, `RUN_NOT_RELEASED`, `RUN_POSTED`, `RUN_CANCELLED`, `NOTHING_TO_POST`, `NEGATIVE_NET_PAY`, `COMPANY_INCOMPLETE`, `PERIOD_MISMATCH`, `PERIOD_CLOSED`, `CURRENCY_DIFFERS`, `NO_NET_PAY_ACCOUNT`, `NO_COST_OBJECT`, `UNBALANCED`; ledger refusals (`GlDocumentError`/`PostingError`/`NumberRangeError`) → `GL_REFUSED`, `PeriodError` → `PERIOD_UNRESOLVED`. `getPayrollPosting` reads the document, totals and `accounting_reversal_link` (a reversal never reopens the run). Pays nobody (phase 4).
- `src/modules/people/payroll-access.ts` — payroll phase 5 (9281): `PayrollAccess` = `{ authorization }` (a session, verified in the service's tx with `verifyServiceAuthorityInTx`; its restrictions decide Company Code reach) or a capability list (trusted in-process callers: demo provisioner, tests; capability only, no scope limit). `judgePayrollAccess(tx, client, access, capabilities[], refuse)` passes on any one capability; `reachesCompany`, `assertCompanyScope` (`COMPANY_SCOPE`). Every payroll service (structures, runs, results, posting/payment readers) takes one; pages and actions pass the session. Reads accept the reading capabilities (structures: STRUCTURE.DEFINE or PAYROLL.RESULT; runs/results: PAYROLLRUN.EXECUTE or PAYROLL.RESULT; posting/payment readers also PAYROLL.POST/PAYMENT). `listPayrollRuns` filters by scope; single reads refuse out of scope.
- `src/modules/people/salary-payment.ts` — payroll phase 4 (9280): `paySalaryRun({client, changedBy, runId, paymentDate, houseBankKey, bankAccountId, authorization})` pays a POSTED run once as a `PY` document (request key `SALARY-PAY-<runId>`): one debit per employee with positive net pay on the `PAYROLL_NET_PAY` account, one credit to `bank_account.gl_account`; no cost object or partner. Reconciles first — the PR document's uncleared credit on that account must equal Σ net pay (`NOTHING_OPEN` / `NET_PAY_MISMATCH`). The `onPosted` hook clears the PR net pay credit and the PY debits (`clearing_document`/`clearing_date`) and inserts `salary_payment`. Authority `PEOPLE.PAYROLL.PAYMENT` + Company Code reach (FIN.JOURNAL.POST asked by the G/L posting). Other refusals: `PAYMENT_AUTHORITY`, `COMPANY_SCOPE`, `RUN_UNKNOWN`, `RUN_NOT_POSTED`, `RUN_BROKEN`, `ALREADY_PAID`, `NEGATIVE_NET_PAY`, `NOTHING_TO_PAY`, `CURRENCY_DIFFERS`, `PAYMENT_DATE`, `PAID_BEFORE_PERIOD_END`, `PERIOD_CLOSED`, `BANK_ACCOUNT_UNKNOWN`, `BANK_CURRENCY`, `HOUSE_BANK_UNKNOWN`, `NO_NET_PAY_ACCOUNT`, `UNBALANCED`, `GL_REFUSED`. Pure `buildSalaryPaymentJournal`; reader `getSalaryPayment` (with reversal flag). No payment medium.
- `src/app/people/payroll-runs/{page.tsx,RunForms.tsx,actions.ts}` — `/people/payroll-runs`: run list, `?run=` header/totals/exceptions, Propose/Recalculate/Release/Cancel, and Post to G/L (RELEASED + `PEOPLE.PAYROLL.POST`; `postPayrollRunAction` takes only `runId`); a POSTED run links its document to `/finance/journal/document?document=` (gated `FIN.JOURNAL.DISPLAY`); a POSTED unpaid run shows `PaySalaryForm` (`paySalaryRunAction`: `runId`, `paymentDate`, `houseBankKey`, `bankAccountId`; banks from `finance/payment-run.listBankChoices`), a paid run its payment.
- `src/app/people/payroll-results/page.tsx` — `/people/payroll-results` (read-only, `PEOPLE.PAYROLL.RESULT`): GET filter `runId`,`personnelNumber`; `?result=` slip with lines.
- `src/modules/people/pay-components.ts` — `pay_component` defs + per-chart GL/cost mapping; validates against `gl_account`, `chart_of_accounts`, `cost_center` (other modules' tables). Exports: `definePayComponent`, `changePayComponent`, `savePayComponentMapping`, `getPayComponent`, `listPayComponents`, `listChartsForMapping`, `listAccountsForSide`, `listCostCentresForMapping`, `isPayComponentError`, `listOpenPayComponents`, `PayComponentError`.
- `src/app/config/pay-components/actions.ts` — `defineComponentAction`, `changeComponentAction`, `defineMappingAction`, `changeMappingAction`; `CLEAR`/`NONE` sentinel: "field not sent" vs "clear field."
- `src/app/config/pay-components/PayComponents.tsx` — client: define component, list, select chart, define/correct mapping (debit/credit selects, cost-receiver choice).
- `src/app/config/pay-components/page.tsx` — `/config/pay-components` page.

**Reads/writes other modules':**

- `cost_center` (foundation/finance controlling) — `assignment.ts`/`pay-components.ts` check it stands (dated, as-of a day) before naming on assignment/FIXED mapping; not a Drizzle FK (PK carries from-date).

- `audit_access_log` (platform security) — every action writes `CAPABILITY_DENIED` via raw SQL (`auditAccessLog` typing-only import) on capability failure.

## Depends on
- **Finance** (`gl_account`, `chart_of_accounts`) — pay mapping checked against tenant's chart of accounts. Payroll posting calls `finance/gl-document.postGlDocument` and reads `journal_entry(_line)`, `accounting_reversal_link`.

- **Foundation/controlling** (`cost_center`) — assignments/FIXED mappings charge real dated cost centre; `position_assignment.controlling_area` real FK, `cost_center` via raw SQL (dated).

- **Platform db** (`platform/db/client`: `withTenant`, `Tx`) — tenant-scoped tx; advisory locks (`pg_advisory_xact_lock`) serialize overlap checks (records/assignments/absences).
- **Platform change** (`recordChange`) — every create/change writes change-history doc (class, before/after, actor).
- **Platform posting/decimal** (`toScaled`/`fromScaled`) — fixed-point arithmetic for leave-quota/time-recording decimals.
- **Platform tenancy tables** (`client`, `auditColumns`) — tenant FK + audit columns on every table.
- **Platform auth authority** (`platform/auth/authority`: `effectiveGrants`, `AuthorityGrant`, `ScopeKey`) — authority chart/delegation read derived grants; two-way coupling (authority imports `people/schema` + `delegation-status`).
- **Platform job/notification** (`platform/job/registry`, `platform/job/types`, `platform/notification/notify`) — grant-expiry job.

## Non-obvious behavior / gotchas
- Payroll phase 1: payroll capabilities (`PEOPLE.PAYROLLRUN.EXECUTE`, `PEOPLE.PAYROLL.RESULT`, `PEOPLE.PAYROLL.IMPORT`, `PEOPLE.PAYROLL.STRUCTURE.DEFINE`) are granted to no role (history/9199 withholds payroll); the demo reaches them via `demo.admin`'s `*`. Readiness covers the days the employee holds a position (joiners/leavers), so a structure starting mid-month on a full-month position is refused with the first uncovered day.
- No deletes: every table append-only/retire-only at DB privilege level (migrations `9193`-`9197` revoke DELETE); exception `org_hierarchy` (app can delete — move = delete+reinsert single edge, not history).
- Overlap checks use advisory lock (`pg_advisory_xact_lock(hashtextextended(...))`) before checking, in `employee-master.ts`/`assignment.ts`/`time-leave.ts` — PK is backstop only; concurrent writers could both see a day as free.
- Only newest *open* record/assignment/mapping-row correctable in place; else new dated row required. `changeRecordValues`/`changeAssignment` enforce "no newer row AND still open."
- Field answer lives in one of 3 columns by kind; `record_field_value` CHECK requires exactly one of `text_value`/`number_value`/`date_value` non-null. Changing `valueKind` while rows answer it refused (`KIND_IN_USE`).
- Cost centre checked via raw SQL, never Drizzle FK (PK carries from-date, can't be a single-interval FK target): `assignment.ts` (`costCenterAsOf`, as of assignment start), `pay-components.ts` (`centreStandingToday`, as of today).
- `pay_component_config` check-constraint bug: `pay_component_config_assignment_needs_nothing_ck` in `schema.ts` has stray `}` in SQL template (`... is null})`) — flag if touching this constraint in migration.
- Org structure NOT dated (unlike rest of module): tree placement is "as of today" only by design (§15.1 puts validity dates on Assignment alone) — can't answer "what did org chart look like last quarter."
- Position never stores holder/vacancy; `incumbents`/`positionsFilled` always computed from `position_assignment` as of today — avoids a second driftable answer.
- `TimeLeave.tsx` time-type `<select>`s never populated: `AbsenceRequestForm`/`TimeRecordingForm`/`LeaveQuotaForm` render `<select name="timeTypeCode">` with blank `—` only, no `.map()` over `timeTypes` — prop reaches parent, not threaded in; UI as-is can't select a real time type (apparent bug vs. polished employee/assignment/org screens).
- One employee holds only one assignment at a time — overlap test in `assignment.ts` scoped to employee, not `(employee, position)`; split/% assignments unsupported; two roles = two sequential non-overlapping spans.
- Delegation stores no capabilities: delegate's authority re-derived from delegator on every check (`effectiveGrants` + `isLive`), so revoking/losing the delegator's grant ends it with no sweep; no `delegation_scope` rows = delegator's own scope inherited.
- Delegation approval side satisfied by *any* approver row on that side (multi-position superiors); a side with no rows (line ends in org unit/apex) is self-approving. `superiorOf(delegator)===superiorOf(delegatee)` → one side only.
- `authority-chart.ts` header comment still says delegation panels are empty "until Phase 5" — stale; it now loads real rows via `delegationsForUser`. Page gates only via `requireSession(AUTHORITY_ROUTE)`; visible set is computed from viewer's positions, never from `?user=`.
- Pay components compute/post nothing: `definePayComponent`/`savePayComponentMapping` only define where an amount *would* go — no run/result/payslip/GL posting anywhere (R-11, DV-001); same for time-leave (`recordTime`/`requestAbsence` never touch payroll).
- **Payroll run (9278):** a released run is frozen — `recalculatePayrollRun` refuses it (`RUN_FROZEN`); a correction is a new run in a later period. Results/exceptions of a PROPOSED run are deleted and rewritten on recalculation (cairn_app has DELETE on those two tables only). Only one non-cancelled run per company/year/period (partial unique index). The open-period check uses account type `S`; special periods (13–16) are refused by `periodDates`. A salary assignment in a currency other than the company's is an exception (`CURRENCY_DIFFERS`) — no conversion is built.
- **Payroll posting (9279):** `payroll_run` checks `(status = 'POSTED') = (document_number is not null)` and the document/year pair, so a run can only become POSTED by carrying its document. Posting needs an explicit Company Code scope (`verifyServiceAuthorityInTx`); the demo's `demo.admin` had none until `D9_PAYROLL_POST` granted it company 1000 and plants 1000/2000. Test tenants have no `RF_BELEG` number range — `tests/payroll-posting.test.ts` maintains one.
- **Salary payment (9280):** results of a POSTED run cannot be updated by `cairn_app` (no UPDATE grant); DELETE stands on `payroll_result` for recalculating PROPOSED runs, and since 9281 the `payroll_result_immutable_trg` trigger refuses it for RELEASED/POSTED runs (a client cascade passes). `salary_payment` has no status: the row exists exactly when the PY document posted. Reversing the PY document leaves the row standing (one payment per run).
- **Payroll 9281 triggers** (`SECURITY DEFINER`, owned by the migrator): `payroll_result_coverage_trg` (before insert/update; one personnel number in one live run per company/year/period, SQLSTATE 23505) replaced the unique index `payroll_run_period_uq`; `payroll_result_immutable_trg` (before delete; RELEASED/POSTED → 23514, passes when the client row is gone so tenant teardown works).
- `tests/payroll-followup.test.ts` — payroll phase 5 (15): off-cycle (exclusion, informational exceptions, predecessor, own PR and PY, all-covered refusal, 23505 trigger, unready-only run), Company Code scope on propose/release/cancel/assign/end, scoped list filtering, out-of-scope get, forged/missing session, 23514 immutability, proposed delete cascades lines, every posting event labelled.
